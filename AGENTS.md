# «Место сгиба» — дневник-скетчбук (Genesis, ArtTech)

Этот файл читают все ассистенты команды (Claude Code, Codex, Antigravity). Решения, которые должны помнить все, дописывайте сюда в том же PR.

## Суть

- Цель: пройти в финал. Срок 22.11 23:59 по Астане, отправляем к 21:30.
- Текст + 1–5 фото + песня → разворот в скетчбуке месяца. Главная фраза подчёркнута, главный снимок появляется на пике песни.
- Главный показ: те же фото + другой рассказ = другая книжка; другая песня = другая плотность рисунков и ритм сборки.
- Положение кейса (первоисточник требований и критериев) — docs/polozhenie-arttech.md.
- План по дням, критерии жюри, что сдать, риски и запасной вариант — docs/plan.md.
- С 20.11 вид дневника — скетчбук по месяцам вместо гармошки: спецификация в docs/sketchbook.md (она главнее docs/mockup.html).

## Правила дня

- Правила описаны в docs/rules.md и живут в src/rules как чистые функции. Один вход → один DaySpec → одна книга.
- Каждое правило пишет причину обычным языком для оборота «Почему так».
- Признаки: текст (переходы, длина фраз, основы тепло/свет/звук, «мы»), фото (главный кадр, цвета, число), музыка (темп, энергия, пик, год, жанр).
- Скетчбук принимает необязательные mood, weather и takenAt. Старые записи без этих полей открываются; погода хранится снимком в DayInput.
- Для формы Дамира: `getDayWeather({ enabled, takenAt, recordedAt, place, signal })` из `src/weather` возвращает снимок или `undefined`. Передать значение переключателя «Добавить погоду» и показать выбранный город. По умолчанию Талдыкорган, при недоступности — Алматы; в результате хранится фактическое место. Сохранить результат в `DayInput.weather` один раз при записи. Рендер не обращается к погодному API.
- Обложка, оглавление и дневные листы используют один переплёт месяца. StPageFlip перелистывает снимки настоящих листов. Наклейки берутся из тематических наборов и размещаются с учётом их размера и поворота.
- Контракт: src/types/dayspec.ts. Отрисовка читает только DaySpec.
- В v2 раскладку листов, материалы заголовка и причины в «Почему так» строит `src/rules/page.ts`. Демо-дни и свои записи проходят через одни правила. Снимки для проверки лентой лежат в `docs/previews/rules`.
- Мраморная обложка месяца получает ярлык, степень потёртости и детали из собранных разворотов. Оглавление использует те же бумагу, отпечатки и пружину, что и записи.
- Главный экран `#/` (src/gallery, идея Дамира в материалах тетрадей) — стол вечером: тетради месяцев и чёрный фотоальбом, где день — отпечаток с подписью, а несколько пустых дней подряд сжаты в одну клетку. `#/gallery/<id>` раскрывает день на том же столе. Тетрадь (`#/month/<месяц>`) и день (`#/day/<id>`) открываются на том же столе. Свет из окна по погоде часа записи, отсвет цвета снимков, снег или дождь, лента носителя песни и вырезанный заголовок берутся из DaySpec; своих правил у экрана нет, разворот рисует тот же `DaySpread`. Соседний день открывается переворотом страницы через `FlipThrough` (StPageFlip). Касание книги приближает её; «Почему так» и ZIP — на том же экране.
- «Записать день» и `#/edit/<id>` открывают редактор листа Дамира (src/input/editor) в материалах стола. Правки автора хранятся в `DayInput.overrides.design` и ложатся поверх результата правил (`rules/sheet.ts` → `page.sheet`); разворот, тетради и перелистывание рисуют их тем же `DaySpread`.
- У разворотов четыре композиции. Выбор зависит от формата главного кадра, числа снимков, длины записи и энергии песни. Эпоха задаёт музыкальный носитель, а предметы берутся из слов записи. Подписи отпечатков можно передать в `PhotoInput.caption`.

## Музыка и права

- iTunes Search API (country=kz) + официальный 30-секундный фрагмент, разбор в Web Audio.
- Храним только trackId, ссылки и признаки. Песни и фрагменты не кладём ни в репозиторий, ни в ZIP, ни в кэш service worker.
- У плеера — значок-ссылка Apple Music и подпись «provided courtesy of iTunes»; звук только потоком через `<audio>`.

## Стек и ограничения

- Vite, TypeScript, React, SVG/CSS, Canvas2D, Web Audio, Dexie, fflate, Vitest, Playwright. Хостинг — GitHub Pages (`base: '/mesto-sgiba/'`).
- Запрещено: сервер, ключи, платные API, языковая модель в продукте, WebGL.
- UI: песня дня звучит сразу, когда человек сам открывает день (касание отпечатка или тетради, перелистывание); при открытии по прямой ссылке и при запрете браузера — по кнопке. Вместо спиннеров — скелетоны по форме контента; уважать prefers-reduced-motion.
- Не резать: три входа, влияние и звучание музыки, папку с названием из 3–7 слов, архив, 3+ дня с разным настроением.

## Проверка

- Контрольные дни — fixtures/days, загрузка через src/fixtures.ts. Тесты правил гоняются на них. Придуманные дни со сгенерированными кадрами помечены `hidden`: в приложении их нет, а Playwright собирает приложение с `VITE_ALL_DEMO=1` и видит их.
- Перед PR: `npm run format`, `npm run lint`, `npm test`, `npm run build`.
- Playwright: путь ввода и ширина 375 px (`npm run e2e`, один раз `npx playwright install chromium`).

## Как мы работаем вдвоём

- Задача начинается с issue на GitHub: кто взял — назначает себя. Две сессии ассистентов не делают одну задачу.
- Направления: vlyalyaps — правила, скетчбук, сборка приложения (с ним работает и Codex); Dahsjs198 — ввод (форма, фото, настроение), поиск и разбор песни, архив и ZIP. Модули общаются только через интерфейсы в src/audio, src/input, src/archive и через DaySpec; сигнатуры меняем по договорённости, как dayspec.ts.
- Каждая задача — своя ветка от свежего main: `git switch main && git pull`, затем `git switch -c <имя>/<задача>`.
- Коммиты маленькие и понятные. Ветка живёт часы, не дни: как только кусок работает, — PR в main.
- Перед PR подтянуть main (`git pull --rebase origin main`) и прогнать проверки выше.
- При конфликте сохраняй обе правки по смыслу, чужой код не выбрасывай. Неясно, чья правка верна, — спроси человека.
- Не переименовывай, не переноси и не переформатируй то, чего не касается задача.
- Новые зависимости — только если без них задача не решается, отдельным коммитом. Нужен npm 11.21 или новее (`npm i -g npm@11`): старый npm на Windows теряет в package-lock.json пакеты для Linux, и `npm ci` в CI падает.
- Конфликт в package-lock.json руками не сливаем: `git checkout origin/main -- package-lock.json`, затем `npm install` и коммит.
- Изменение src/types/dayspec.ts — отдельный маленький PR, второй человек должен о нём знать.
- main защищён на GitHub: только через PR, слияние squash и только при зелёной проверке CI, force push и удаление запрещены. Ветка после слияния удаляется сама. Чтобы PR влился сам после зелёной проверки: `gh pr merge --auto --squash`.
- Коммиты и PR — без подписей и соавторства ИИ-ассистентов.
